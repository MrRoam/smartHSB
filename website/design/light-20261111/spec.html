1. 方向与关键决定

以白色建立阅读秩序，以薄荷和冰蓝划分内容层次，以亮绿引导主要行动。产品展示承担主要视觉重量。金融信息依靠清晰的文字、数字、边界和条件建立可信度。

决定 解决的问题 本稿如何表现
常规内容区全面浅色 连续深底使信息显重，弱化产品细节 白 → 薄荷光白 → 白色产品舞台 → 冰蓝市场区 → 白/柔白信息区
原光门保留炭黑舞台，浅色从其后开始 原视频、人物和雾以明暗关系成立；白底直接参与 screen 合成会洗白画面 场景一展示原光门真实静帧，下一内容区在独立浅底上开始；光色不盖住徽章
平台区产品占约 55% 的横向空间 参考站的层次来自产品比例，不能只换背景色 桌面文案左、产品右；手机文案在前，产品完整置于下方
市场区回到实色白面和清晰列表 行情、名称、条件需要稳定阅读 冰蓝外底、白面板、深绿选中态；四类共 25 品种全部可切换
只保留一处虹彩次按钮 彩边过多会与主行动竞争 平台区的“试用模拟账户”；其他次行动用文字链接
新内容区只演示一组持续浮动 同时运动会分散读者对行情与条件的注意 桌面仅模拟账户浮卡；手机关闭；渐变均静态

本稿推荐的是“浅色内容 + 保留原光门”的方案。 这不等于全浅色光门已经解决。若要求首屏本身也完全浅色，需要先确认下述合成研究方向，再实施。

光门为什么不能只改背景

实际源码 website/assets/js/intro-portal.js 的 drawVideoScene() 先填纯黑，绘制视频并镜像去除内嵌文字，再用黑色侧缘、顶部和底部遮罩消隐；最后以 globalCompositeOperation = 'screen' 叠加 #1B1B1B。intro-portal.css 也以此炭黑为舞台底色。

screen 每通道公式为 1 − (1 − 源) × (1 − 底)。当参与合成的颜色为白色时结果恒为白色。仅改容器 CSS 不会改变 Canvas 中已绘制的黑色；把最终 screen 色改成白色则会抹去图像。两种改法均不成立。

本稿没有对视频反色、覆盖浅色大蒙层或替换人物。原门、人物、文案、视频、时序及六徽章由现有页面真实静帧表达。蓝绿光带放在下一内容区的顶部，保持两个场景各自清晰。

待研究的全浅色光门方向： 原视频不变，在独立实验中重建明暗分离及羽化蒙版，限制调色只影响环境和边缘，保留门光与人物剪影。需逐帧核对 0.05 / 1.5 / 3 / 4.5 / 6.0 秒，以及五档宽度；检查内嵌文字移除、雾边、倒影、人物和徽章。当前仅提出研究路线，未制作或验证此版本。若无法同时保留门光层次与原画面关系，继续采用本稿的原光门方案。

3. 色板与语义

面积起点：75% 白/柔白、15% 浅蓝/浅薄荷、8% 绿青强调、2% 功能蓝及补色。仅用于浅色内容构图；不将保留的光门面积算入此比例，也不把它声称为实测结果。每区块一个主强调色，最多一个辅助色；柔光混色与虹彩边框作为有限的装饰配方例外，不承担状态语义。

对比度验收

使用 WCAG 相对亮度公式计算，普通字 ≥4.5:1，大字 ≥3:1；焦点与必要的控件边界 ≥3:1。具体组合见 contrast.json。主要结果在验收报告中列出。

信息文字位于实色白面或确定的浅底。平台柔光中心在右侧，左侧文案区的叠色量较低；验收同时采样实际合成背景，而非只测设计令牌。亮色按钮使用深墨文字并有深绿细边。虹彩边框是装饰，按钮文字和外部焦点仍单独达标。

三个重点场景

  1. 光门与浅色内容衔接。 原 HERO 独立保留，后接浅薄荷光白底。沿用“一个账户。打开全球市场。”和现有说明；四类市场计数直接铺在一条分隔线上。解决原光门和浅色内容像两套主题的问题，同时不改已有影像。
  2. 平台产品区。 采用现有“从看见机会，到把握机会”、两项平台说明和下载入口。使用现有网页手机示例中的文字、虚拟资金与报价，按新材质绘制其外部舞台。该示意不是新 APP 截图，也不承诺 APP 将增加白色皮肤。右上分析卡和左下模拟账户卡形成前后层次。解决平台产品面积偏小、信息与产品分离的问题。
  3. 市场区。 原四分类、25 品种、中文名、示例报价和代表图表数据来自当前首页/脚本。Tab 用深绿边线、浅薄荷底及 aria-selected 表达选择；列表回到白底。解决亮色冲淡数据层次和手机列表难以浏览的问题。

三个场景的实际文案均出现在审阅稿中。市场和设备旁明确写“非实时/展示示例”，模拟账户写“虚拟资金”，不把上涨示例或设备画面当作收益承诺。
